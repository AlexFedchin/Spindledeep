The Ghost on the Title Screen

Found, reproduced and fixedplus a log of every session in case anything else goes wrong

The game wasn't crashing or reloading. It was being told to start a new game. The title screen's buttons stayed alive, invisible, while you played. If you had clicked Begin or Begin anew with the mouse, that button kept keyboard focus after the title faded out. The next press of Enter (the act key, used to tie and to mend the thread) or Space clicked it again. That replayed the prologue and started a new run over your save.

It looked random because it only happened after a mouse click on the title and only on the next Enter or Space that reached the button. Pressing Enter right after a death, to mend the cut thread, is exactly the moment it fires.

What happened

There is still some real bug with the game randomly restarting from the very beginning. Without any checkpoints, just from the opening cutscene. This time it happened right after I died one time.

Reproduced in a test run with real mouse and keyboard events, in the invisible test window:

  • Hidden screens are now inert. When the title, pause menu or any other overlay fades out, it's also switched off completely, so nothing on it can hold focus or be clicked.
  • Menu buttons never take focus, even when clicked with the mouse. The menus are driven by the game's own input, as they always were from the keyboard and gamepad.
  • Each menu acts only on its own screen: the title menu on the title, the pause menu while paused. If something like this ever happens again, it's refused and written to the log.

The session log

Every launch now writes a plain-text log. If something strange happens, send me the newest file from:

%APPDATA%\Spindledeep\logs\One session-…log per launch, newest last, 10 kept. Paste that path into the Explorer address bar to open it.
  • What it records: each screen (title, films, play, credits); every menu choice and whether it came from the mouse or the keys; each new run and continue; every save and the pole it was at, with a warning if writing the file failed; deaths with their cause and place; respawns; poles tied; areas entered; pause and resume.
  • Problems: script errors with file and line, a film that fails to play, a lost GPU device, the game process crashing or hanging, and the window closing.
  • Nothing personal: no keystroke log and no file paths beyond the game's own profile folder. Everything stays on your PC until you send it.
